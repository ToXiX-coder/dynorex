## Decisions to make before coding (recommendations included)

1. **When is the username chosen?** `users.username` is required today, but signup collects only email +
   password. _Recommendation:_ create the profile row automatically at signup with `username = null`,
   then ask for a username right after email verification and before the 3 onboarding steps.
   Following and publishing stay blocked until a username exists. Needs a small Phase 2 migration.
2. **Error copy D-07** (spec's server-error text breaks its own length rule). Pick a shorter version or keep it.
3. **Analytics vendor D-05.** Not blocking: events stay local until chosen.

## Phase 2 build plan (unchanged scope)

1. Migration 2: nullable-username + profile-complete gate, `blocks`, `mutes`, `reports`, `admin_moderation`
   (audit), rate-limit counters; RLS + denial tests for each (follow/view blocked users through every path).
2. Edge Functions: `delete-account` (requires recent sign-in, removes auth user → cascades),
   `export-data`, rate-limited wrappers for sign-up/resend/reset per the spec 13 table.
3. Screens: splash (Torq + logo, reduced-motion static), sign up / sign in / verify / reset,
   username, 3-step onboarding with Skip and server-side resume, profile view/edit, Settings sections that
   save only after the server confirms, block/report/mute.
4. Deep-link handling for `dynorex://auth/callback` and `reset-password`; route guards (UX only; RLS enforces).
5. Exit gate tests per handoff spec Phase 2.
